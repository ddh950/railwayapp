# Railway Live

Railway Live is a simple simulation application built with JavaScript and Node.js and deployed on AWS Elastic Beanstalk.

## Overview

The application simulates an IoT use case using a WebSocket connection. It displays the positions of trains and tracks people moving through the railway environment.

The simulation runs entirely on the server. The data is hard-coded and generated by the application; no database is connected.

In a production environment, IoT data is typically ingested through services such as Amazon Kinesis or MQTT-based messaging systems and stored in a database. The server then provides the relevant data to clients for real-time monitoring.

## Architecture

- **AWS Elastic Beanstalk** – Hosts the Node.js application.
- **Node.js** – Runs the simulation and handles server-side logic.
- **WebSockets** – Provide real-time, bidirectional communication between the server and clients.
- **AWS CloudFormation** – Deploys and manages the required AWS infrastructure.
- **Amazon Cognito (optional)** – Provides user authentication and login functionality.

## Deployment

### Prerequisites

- An AWS account
- An AWS Region supported by Elastic Beanstalk
- An S3 bucket for the application package
- An S3 bucket for the CloudFormation templates

Both bucket names must be globally unique.

### Setup

1. Create two S3 buckets: one for the application package and one for the CloudFormation templates.
2. Update the bucket names and other required parameters in `railway-app.yml`.
3. Upload the application package and CloudFormation templates to the corresponding S3 buckets.
4. Deploy the infrastructure using the CloudFormation stack in the AWS Console or through the AWS CLI.
5. Configure optional settings such as a custom domain, TLS certificates, and health checks.

### Authentication

Amazon Cognito can be used to add user authentication. The application can be configured using the existing Cognito implementation and the corresponding AWS documentation.

## Production Considerations

### IoT Communication

For production IoT workloads, Server-Sent Events (SSE) or MQTT may be suitable alternatives, depending on the communication requirements.

- **SSE** is suitable when data primarily flows from the server to clients.
- **MQTT** is designed for lightweight messaging between IoT devices and services.
- **WebSockets** are useful when bidirectional, real-time communication is required.

The appropriate protocol depends on the expected message volume, latency requirements, and communication patterns.

### Automated Deployment

Application updates can be automated using GitHub Actions and Amazon S3, together with Elastic Beanstalk application version deployments.

As a security best practice, GitHub Actions should authenticate with AWS using OpenID Connect (OIDC) and an IAM role with a trust policy, rather than storing long-lived AWS access keys in GitHub secrets.
